- Geolocation and connectivity adapters.
- Local persistence and secure local storage dependencies.

- Emergency service capable of capturing a location snapshot and launching 112.
- Trusted-contact and Rescue Link modules already separated from UI.
- Wildlife and pet feature areas.
- Brand/design-system documentation with light, dark and high-contrast modes.
- CI plus a separate security workflow.

## Critical current gap

The latest master commit reverted an offline service that had been added accidentally. The offline region lifecycle remains on master, but the concrete provider bridge is therefore not currently confirmed as present. The MVP must not claim that offline map downloading is production-ready until a concrete, licensed offline source/provider is integrated and tested.

## Immediate priorities

1. Preserve the provider-neutral `MapService` boundary.
2. Make offline map provider integration concrete without using the public OSM tile server for bulk/offline prefetching.
3. Add real test coverage around offline lifecycle, weather parsing/cache, GPX, location and emergency safety paths.
4. Harden emergency telemetry: battery/connectivity metadata currently has an explicit unknown sentinel and should be capability-driven rather than fabricated.
5. Keep AEMET credentials strictly in runtime configuration; add cache/failover/timeout policy before production.
6. Add production release gates: dependency/license inventory, secret scanning, static analysis, test matrix, build artifacts and release provenance.
7. Continue Phase 1 in parallel: route state, hazards, water/coverage data contracts, route safety assessment, offline critical data and SOS UX.

## Architectural decision

Do not prematurely split the Flutter MVP into many deployable microservices. Keep domain/service boundaries explicit and provider-neutral in the client, while reserving backend service seams for routes, live data, alerts, emergency coordination and community ingestion. Introduce event-driven infrastructure only where event semantics materially improve reliability or auditability.

## Non-negotiable safety rule

No live alert, rescue recommendation, hazard state or AI result may be presented as authoritative without provenance, freshness and confidence metadata. Rescue Link must never dispatch volunteers into known official closures, evacuation areas, active fire zones or similarly blocked hazards.
