# ESPAÑA OUTDOOR — AUDITORÍA TÉCNICA Y CATÁLOGO DE SOFTWARE MADURO

Fecha: 2026-09-23
Alcance: Android + iOS/iPadOS únicamente.

## Principio maestro

Reutilizar software maduro para capas genéricas y reservar código propio para routing outdoor, seguridad, información viva, conservación, Rescue Link y la experiencia España Outdoor. Ninguna dependencia se incorpora solo por existir: se revisan mantenimiento, licencia, seguridad, soporte móvil, rendimiento, coste, lock-in y procedencia.

## Trabajo aplicado en esta fase

- MapLibre quedó como renderer móvil único; se eliminaron los caminos Web/desktop y flutter_map.
- Geolocator quedó configurado para background location en Android/iOS con los ajustes nativos necesarios.
- Las sesiones de grabación GPS ahora se persisten por segmentos y pueden recuperarse después de una interrupción del proceso.
- EmergencyService usa battery_plus para el nivel de batería.
- El fallback SMS/copiar de emergencia ya no expone coordenadas exactas; usa ubicación aproximada.
- Rescue Link dispone de contrato de gateway HTTPS y ahora incluye un backend Go con tokens opacos, revocación, expiración server-side, capacidades temporales y coordenadas cifradas.
- La cola offline dispone de almacenamiento Hive durable, idempotencia de enqueue, prioridades y reintentos acotados con backoff.
- Los paquetes PMTiles pueden verificarse mediante SHA-256 antes de activarse.
- CI y Security baseline quedaron alineados con el alcance móvil Android/iOS y los nuevos tests de seguridad/offline/backend.

## Riesgos de alta prioridad aún abiertos

1. Rescue Link necesita despliegue real con Keycloak configurado, roles verificados, HTTPS y pruebas de integración.
2. La cola offline ya tiene persistencia y retry, pero todavía necesita ejecutores reales por tipo de operación y reconciliación contra el backend.
3. La verificación SHA-256 está implementada en el downloader, pero la integración definitiva debe exigir checksum en el catálogo de producción y verificar antes de marcar una región como lista.
5. El CI está actualizado con tests adicionales de Rescue Link, sincronización offline y Source Gateway, pero el resultado de ejecución del push actual no está disponible a través del conector de GitHub; no se marca como verde sin evidencia.
4. Las APIs/contratos de plataforma siguen teniendo duplicaciones entre platform_services.dart y contratos específicos; la consolidación debe hacerse con análisis de referencias antes de eliminar símbolos.

## Riesgos de prioridad media

- OfflineRegionManager usa un busy global.
- Hive debe evolucionar hacia SQLite/Drift cuando necesitemos consultas, relaciones, índices geográficos y migraciones complejas.
- Source Gateway necesita circuit breaker/fallback real en backend; el cliente ahora falla cerrado ante metadatos de frescura inválidos y obliga a HTTPS.
- La cola OfflineSync conserva las operaciones agotadas como estado `failed`; no se eliminan silenciosamente tras superar los reintentos.
- Risk Engine debe distinguir ausencia de evidencia de evidencia negativa.
- AIService sigue siendo un contrato demasiado genérico para una capa crítica; ninguna decisión de seguridad debe depender directamente de una respuesta libre de IA.
- Push FCM/APNs queda pendiente hasta disponer de infraestructura backend de notificaciones.

## Regla de release

Antes de producción: flutter analyze, suite completa de tests, pruebas offline con conectividad desactivada, pruebas reales SOS/112 en hardware soportado, revisión de licencias, SBOM, Gitleaks, Trivy, Go vet/tests y pruebas de integración del backend de Rescue Link.
