# ESPAÑA OUTDOOR — AUDITORÍA TÉCNICA Y CATÁLOGO DE SOFTWARE MADURO

Fecha: 2026-09-23
Alcance: Android + iOS/iPadOS únicamente.

## Resumen ejecutivo

La arquitectura actual es razonable, pero hay varios componentes que todavía pueden simplificarse y algunos huecos técnicos que debemos cerrar antes de producción.

Regla de esta auditoría: reutilizar software maduro cuando resuelva una parte genérica y reservar código propio para la inteligencia outdoor, seguridad, conservación y experiencia de producto.

## Código que no necesitamos mantener

### Eliminar ahora

1. flutter_map como renderer móvil alternativo. MapLibre GL ya es el renderer objetivo para Android/iOS y soporta MVT, PMTiles, estilos vectoriales y regiones offline. Mantener dos renderers aumenta superficie de bugs y testing.
2. lib/features/map/map_provider_config.dart. Su finalidad principal era el fallback raster de escritorio/OSM.
3. lib/core/map/maplibre_style_provider_web.dart. Web queda fuera del producto actual.
4. Código de fallback de escritorio en map_page.dart. Windows/macOS/Linux están fuera del alcance actual.
5. Referencias documentales a flutter_map_mbtiles como dependencia activa. No aparece en pubspec.yaml y debe eliminarse del registro si no se utiliza.

## Problemas o riesgos detectados

### Alta prioridad

1. Grabación GPS foreground-only. RouteRecorder usa Geolocator.getPositionStream con LocationSettings genérico. No existe todavía una política completa de localización en segundo plano para Android/iOS ni persistencia incremental de puntos durante sesiones largas.

Acción: aprovechar las capacidades de background location de geolocator antes de introducir otro SDK; configurar Android/iOS; persistir segmentos de track periódicamente; recuperar sesiones tras interrupción.

2. SOS sin batería real. EmergencyService devuelve batteryPercent = -1.

Acción: incorporar battery_plus.

3. Compartición de emergencia. El sistema actual genera un token local y un SMS con coordenadas exactas. La caducidad es principalmente lógica del cliente y todavía no existe un servidor que pueda revocar o limitar el acceso.

Acción: compartir primero ubicación aproximada; después implementar token temporal de backend, expiración real, revocación y autorización; solo tras aceptación exponer la posición exacta mínima necesaria.

4. Offline Sync es todavía un contrato. OfflineSyncStore y OfflineSyncEngine están definidos, pero falta implementación durable con reintentos, idempotencia, backoff y reconciliación.

Acción: evaluar Drift/SQLite como base de datos local robusta; evaluar PowerSync solo si su modelo de licencia y operación compensa el lock-in.

5. Duplicación de contratos. Existen modelos y contratos paralelos en platform_services.dart y otros contratos específicos.

Acción: consolidar contratos y tipos GIS en un único dominio y eliminar duplicaciones sin romper imports existentes.

### Prioridad media

- OfflineRegionManager usa un busy global; puede evolucionar a operaciones concurrentes por región.
- El almacenamiento de rutas está orientado a Hive; para consultas geográficas, sincronización y relaciones será más mantenible SQLite/Drift.
- La caché meteorológica necesita TTL explícito y stale-while-revalidate.
- El modelo de fuentes necesita circuit breaker/fallback real en backend.
- El Risk Engine debe distinguir falta de datos de evidencia negativa.
- AIService sigue siendo demasiado genérico para una capa crítica; decisiones de seguridad deben quedar fuera de la IA.
- SOS debe añadir batería, conectividad y hora con datos reales; no usar placeholders en producción.

## Evidencia técnica

- MapLibre GL 0.27.1 soporta Android/iOS, MVT y PMTiles, y ofrece regiones offline en Android/iOS.
- Martin sirve vector tiles desde PostGIS, PMTiles y MBTiles y permite generación y validación de tiles; licencia Apache-2.0 o MIT.
- H3 de Uber está bajo Apache 2.0 y es adecuado para indexación espacial jerárquica.
- battery_plus 7.1.1 soporta Android e iOS.
- firebase_messaging 16.7.0 es el plugin oficial de Flutter para FCM y soporta Android/iOS.
- Drift 2.35.0 aporta SQLite, migraciones, transacciones y FTS5.
- bgeo_background_geolocation incluye tracking background, geofences y eventos con la app terminada, pero el motor es cerrado, requiere licencia en release y el uploader no está verificado.
- PowerSync tiene cliente Apache-2.0, pero debemos revisar las condiciones del servidor antes de adoptarlo.

## Decisiones

### Adoptar ahora
- battery_plus.
- limpieza de flutter_map y código de escritorio/Web.
- consolidación de contratos.
- preparación de Drift como futura base de datos local.

### Adoptar durante el MVP ampliado
- firebase_messaging.
- Martin en backend.
- H3 en backend.

### Evaluar antes de producción
- Tippecanoe.
- PowerSync.

### No adoptar
- bgeo_background_geolocation por dependencia de motor propietario/licencia y baja madurez pública.
- flutter_foreground_task como motor de tracking continuo en iOS.
- libre_location salvo necesidad específica.
- BRouter como router principal multiplataforma.

## Resultado

El principio queda fijado: comprar/reutilizar infraestructura madura; programar solo lo que hace diferente a ESPAÑA OUTDOOR.

La siguiente fase de esta auditoría es aplicar las eliminaciones seguras, integrar battery_plus, y preparar la migración de persistencia y sincronización sin romper la app.
