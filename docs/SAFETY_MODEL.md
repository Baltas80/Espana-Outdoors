# España Outdoor — Safety Model v0.1

## Scope

Safety information is contextual guidance and must never be presented as a substitute for professional emergency services.

## Hazard classes

- Weather
- Fire
- Flood
- Heat/cold
- Terrain
- Water
- Wildlife
- Route closure/restriction
- Human/security incident
- Connectivity/GPS degradation

## Source priority

1. Official emergency/government source
2. Official protected-area or land-manager source
3. Verified operational source
4. Community report
5. Model-generated suggestion

Lower-priority information must never silently override a higher-priority official warning.

## Emergency escalation

Normal flow:

1. Detect or receive an incident.
2. Present concise actionable information.
3. If the user activates SOS, prioritise professional emergency contact capabilities.
4. Offer trusted-contact sharing with explicit confirmation.
5. Rescue Link may alert eligible nearby app users only under a controlled protocol.
6. Never disclose more location or identity than necessary.

## Rescue Link safeguards

- Explicit opt-in for receiving community emergency alerts.
- No public exact-location feed.
- Rate limits and abuse controls.
- Short-lived emergency sessions.
- Automatic expiry.
- Revocation.
- Anti-stalking protections.
- Clear distinction between official emergency response and community assistance.
- No instruction that encourages untrained users to enter dangerous areas.

## Location policy

Exact location is sensitive. It must be collected only when required by an enabled feature, explained to the user, and deleted or expired according to the purpose.

## Offline safety

Critical safety information already downloaded should remain accessible without connectivity. The UI must show when dynamic data cannot be refreshed.

## Stale data

Safety records must carry freshness metadata. A stale record is not equivalent to a current warning.
